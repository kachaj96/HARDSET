# HARDSET — Rule Catalog & Verification Responsibilities

This catalog prevents confusing a **deterministic syntactic check** with a biological, biomechanical or clinical judgment.

| Rule | Chapter | Automatable with declared inputs? | Necessary manual judgment |
|---|---|---|---|
| All 12 Fixed Core areas present | 02, 09 | Yes | Whether declared priorities fit actual goal |
| Functional Overrides explicit, no silent fixed-map change | 02, 09 | Yes | Whether target is relevant |
| Every exercise has one meaningful Movement Tag | 02 | Yes for field presence | Whether assigned pattern matches mechanics |
| P/S/—/? classification declared | 02 | Yes for syntax | **Whether it represents real stimulus** |
| S? not counted as exposure | 02 | Yes | Whether S can be made credible |
| Max 1 exposure per area/session | 02 | Yes | None beyond data accuracy |
| 2 credible exposures for Priority/Standard default | 02, 06 | Yes | Acceptance of real trade-offs and functional gaps |
| 2 Hard Sets default; 1/3 explained | 03 | Yes | Whether Purpose/Value/Recovery justification is reasonable |
| RIR prescription supplied | 01, 03 | Yes | Accuracy of estimate and effort suitability |
| 0 RIR demands safe termination | 01, 04 | Yes for safety attestation | **Physical verification of set-stop procedure** |
| Relevant stimulus, safe execution, recoverable non-target fatigue | 04 | No, not from exercise name | Exercise selection/individual context |
| Lead-Set qualified progression | 05 | Partially | Technical repeatability and readiness |
| Weekly dose justified via Baseline + Response | 06 | No numeric universal formula | History and current response |
| Time fits capacity | 06, 09 | Approximation | Equipment availability, true workout duration |
| Split follows stimulus and capacity | 06 | Partly | Fit and sustainability |
| Distinguish performance from hypertrophy outcome | 07 | Can enforce labels | Interpretation of measurement validity |
| Evidence-Limited Evaluation with four states | 07 | Partly | Strength of actual outcome evidence |
| Focus Block is optional, maintenance not deload | 08 | Can enforce vocabulary | Goal and phase decision |
| PASS/CONDITIONAL/FAIL from rule gates | 09 | Yes for mapped checks | Final clinical and training plausibility |

**Implementation warning:** Future application logic must not upgrade any `Manual judgment` row into a hard-coded guess merely because automation would be convenient. A testable engine should evaluate facts it has, report uncertainty for facts it does not, and stop when a risk blocks safe programming.
