# HARDSET — Chapter 01: Effort, Hard Sets & Muscular Failure

**Version:** v1.0 — APPROVED RULESET  
**Text status:** faithful editorial reconstruction of approved decisions; not guaranteed verbatim reproduction.  
**Principle:** **High effort is standard. Failure is a tool. Progression is the test.**

## 1. Purpose and scope

HARDSET defines a **Hard Set** as a genuine working set performed with deliberate, repeatable technique, sufficient effort for the exercise and a clear training purpose. Warm-up or ramp-up sets prepare for working sets and **never count** as Hard Sets. Not every set that feels hard is useful: compromised range of motion, uncontrolled momentum or an unsafe stopping point invalidate the intended standard.

The training philosophy favors a small number of **high-quality, high-effort sets per exercise**, rather than accumulation of fatigue for its own sake. This is a programming preference, not a claim that two sets are biologically optimal for all people, muscles or goals.

## 2. Repetitions in reserve (RIR)

- **RIR 2:** approximately two additional technically valid repetitions could have been completed.
- **RIR 1:** approximately one additional technically valid repetition remained.
- **RIR 0:** no additional repetition could be completed with the **same required technique, intended range of motion and exercise standard**. No deliberately failed repetition is needed to establish this stopping boundary.
- RIR is an **estimate**, sensitive to exercise, load, experience and fatigue. Treat it as a control signal, not a laboratory measurement [R04][R19][R20].

A technically invalid repetition is not permission to pursue a higher number. The planned standard defines where the set ends. Distinguish **technical limitation** (movement no longer meets standard) from the narrower idea of momentary concentric muscular failure. HARDSET's practical stopping rule prevents attempts to force unsafe repetitions.

## 3. Default effort architecture

For a default two-set exercise:

| Series | Target | Interpretation |
|---|---|---|
| Hard Set 1 | ~1 RIR | Lead Set: high effort, comparable execution, primary progression signal |
| Hard Set 2 | 0–1 RIR **when safely accessible** | Supporting Set; avoid unnecessary failed reps |

For movements where a very hard endpoint presents disproportionate risk, **1–2 RIR is appropriate**, sometimes for both sets (e.g. free barbell movement without a safely usable stop, or highly fatiguing hinge). For single-set supplementary work, ~0–1 RIR can be appropriate if safe. For three sets, the practical pattern ~1/1/0–1 RIR can be used with the same safety exception. These are prescriptions, not rigid diagnostic thresholds.

## 4. Safety and failure access

A planned 0 RIR set is allowed only when the user can **end the set safely**, including when the next repetition would not be possible. Examples can include suitable selectorized machines or supported isolations; a bench press without correctly set safeties is not a failure-compatible choice. Even a rack does not guarantee risk-free training. HARDSET does not demand failure to prove effort [R03][R05][R06].

Safety and repeatability outrank the goal of hitting an exact RIR. If technique changes, pain arises or safe termination becomes uncertain, stop or modify. HARDSET does not replace clinical assessment where symptoms require it.

## 5. Quality controls

A valid Hard Set requires:

1. A stated movement standard and repeatable useful ROM.
2. No deliberate shortening of ROM to inflate repetitions.
3. Controlled eccentric and intentional concentric; not an obligatory exaggerated tempo.
4. An honest RIR estimate where feasible.
5. A safe stopping strategy and sufficient recovery to maintain output.
6. Comparable logging over time.

Do not confuse **soreness, pump, sweating or exhaustion** with evidence of muscular growth. The planned exercise should produce a relevant stimulus at a manageable cost.

## 6. Scientific boundaries

Research does not establish that momentary failure is universally necessary for hypertrophy; some evidence suggests greater hypertrophy closer to failure, but precision of exact RIR prescriptions is uncertain [R03][R04][R05][R06]. **HARDSET decision:** adopt high-effort work centered on ~1 and 0–1 RIR when safe. **Not a research claim:** those exact two targets outperform every other loading model.

## 7. Interfaces to other chapters

Chapter 03 determines number of sets, reps and rest. Chapter 04 decides whether the selected exercise permits the intended stopping point. Chapter 05 determines progression. Chapters 06–09 ensure that the accumulation of Hard Sets across a week is appropriate to goals, feasible and reviewed.

# HARDSET — Chapter 02: Pattern-Based Exercise Architecture

**Version:** v1.0 — APPROVED RULESET  
**Text status:** faithful editorial reconstruction of approved decisions; not guaranteed verbatim reproduction.  
**Principle:** **Pattern-Led, Muscle-Verified.**

## 1. Why patterns are not enough

Exercise selection starts with useful movement patterns, then verifies which muscle regions receive meaningful stimulus. Merely performing a pattern (e.g. 'push', 'squat') does not prove every participating muscle has received an adequate hypertrophic dose. Conversely, a muscle can be meaningfully trained through multiple patterns. HARDSET avoids mandatory exercise checklists that create redundancy.

## 2. Two exercise families

**Compound Patterns:** multi-joint tasks organized by movement (horizontal/vertical press, horizontal/vertical pull, squat/knee-dominant, hinge/hip-dominant and related patterns).  
**Targeted Functions:** deliberate training of a muscle or function (elbow flexion/extension, lateral shoulder abduction, knee flexion, plantar flexion, etc.).

These families are **not a prestige hierarchy**. Compounds are not inherently superior for every local hypertrophy target. Assign each exercise one primary **Movement Tag** and optional descriptors, while allowing multiple muscle-effect labels.

## 3. Fixed Core — 12 reporting areas

The map organizes structural coverage, not anatomy in its entirety:

| Region | HARDSET area |
|---|---|
| Upper Push | Chest |
| Upper Push | Lateral Delts |
| Upper Push | Elbow Extensors |
| Upper Pull | Back |
| Upper Pull | Rear Delts |
| Upper Pull | Elbow Flexors |
| Lower | Quadriceps |
| Lower | Hamstrings |
| Lower | Glutes |
| Lower | Hip Adductors |
| Lower | Calves |
| Trunk | Trunk Musculature |

**Back** and **Trunk Musculature** are broad reporting areas: when exercise selection depends on differences within them, add **Functional Notes** rather than pretending one P label guarantees all regional functions. For example, lat-biased pulldown and upper-back-biased row may not be interchangeable for every goal.

## 4. Muscle-stimulus labels

- **P — Primary:** muscle/region is a deliberate principal target, with meaningful hard sets under the selected execution.
- **S — Secondary:** a materially trained contributor, but not the principal target.
- **—:** no meaningful stimulus established for this programming purpose.
- **? — uncertain:** evidence or technique is insufficient; for example **S?**. Uncertain stimulus **does not automatically count** toward coverage or exposures.

Labels are **exercise-variant and execution dependent**, not immutable properties of a name. They must be defensible based on the actual mechanics. Do not assign a fixed multiplier such as S = 0.5 P. The fractional approach in statistical literature models data; it is not universal biological equivalence [R02].

## 5. Exposure definition

A weekly **Exposure** for area X is a training session containing ≥1 meaningful Hard Set classified **P or credible S** for X. One session yields **at most one exposure** for an area, regardless of sets or exercises. If both P and S occur, label the session **P**. Ambiguous S? is not credited.

For **Priority** and **Standard**, a **default of two weekly exposures** applies:

- **Priority:** prefer **P + P**; **P + S** is acceptable when S is credible and no important functional gap remains.
- **Standard:** **P + P** or credible **P + S**.
- **S + S:** not automatically sufficient for Priority or Standard.
- **Optional:** no mandatory minimum sets or exposures.

The two-exposure rule is an **organizational default**: not a scientific claim that lower frequency cannot build muscle. Volume-equated hypertrophy comparisons commonly show no meaningful difference by frequency [R10][R11]. If frequency is impossible given constraints, document an **explicit exception** rather than inventing an exposure.

## 6. Dynamic priorities

Assign each Fixed Core area a role per person and time period:

- **Priority:** preferential allocation of quality work and resources.
- **Standard:** consistent stimulus appropriate to agreed goals.
- **Optional:** may receive no direct work without breaking the plan.

No area is inherently Priority; upper and lower body are not assigned default importance. Do not silently change user-selected statuses to resolve a crowded schedule.

## 7. Functional Notes and Overrides

A **Functional Note** disambiguates important characteristics of a broad area without expanding the formal Fixed Core (e.g. spinal stability, trunk rotation; hamstrings by knee flexion versus hip extension; back emphasis). Use notes only if they change selection or validation.

A **Functional Override** is an explicit additional training target outside the 12-area report, such as hip abduction or a particular muscle function. It inherits normal Priority/Standard rules for exposure and coverage, **without permanently becoming a thirteenth Fixed Core area**. Overrides may be removed if the goal changes.

## 8. Coverage audit

Every plan should show a ledger per area: selected priority; P sets; relevant S work; exposure count/type; functional concerns; and any accepted exceptions. Passing structural coverage **does not prove adequate hypertrophy** — that requires observation under Chapters 06–07.

# HARDSET — Chapter 03: Set Architecture

**Version:** v1.0 — APPROVED RULESET  
**Text status:** faithful editorial reconstruction of approved decisions; not guaranteed verbatim reproduction.  
**Principles:** **Adaptive Dual-Set; Two-Set Default; Priority-Aware Volume.**

## 1. One exercise is not a weekly program

A default of **two Hard Sets per exercise** is the central organizational choice. It permits high effort and comparability while controlling session cost. It does **not** mean every area must receive only two sets per week or that two is a universal physiological optimum. Multiple exercises and exposures can accumulate higher weekly volume where warranted [R01][R02][R07].

## 2. Allowed set architectures

| Hard sets | Role | Practical effort pattern |
|---:|---|---|
| 1 | Supplementary work, time constraints or justified low-dose addition | Often 0–1 RIR if failure-safe |
| **2** | **Default** | ~1 RIR then 0–1 RIR where safe |
| 3 | Specific additional value, including from the outset or after monitoring | Often ~1 / ~1 / 0–1 RIR where safe |
| More | Not automatically forbidden; requires stronger workload justification and revision of template | Personalized |

The conditions for 1 or 3 sets are **Purpose / Value / Recovery**. Do not impose an arbitrary cap on three in situations where more work could be appropriate. Adding sets must not compromise exercise quality, the available time budget or other priority work.

## 3. Repetition templates

- **5–8:** heavier strength-biased compound work.
- **6–10:** general compound range.
- **8–12:** targeted or stable machine work.
- **12–20:** controlled isolation work.

These are flexible HARDSET templates, **not exclusive effective hypertrophy ranges**. When a user chooses a range for a tracked variant, preserve it across the comparison block unless there is reason to change it. Loads across a wide repetition spectrum can promote hypertrophy; heavier loads may be advantageous for testing maximum dynamic strength [R17].

## 4. Load handling

Default: **same load for both Hard Sets** to preserve comparability. A controlled **back-off of roughly 5–10%** is available if the later set would otherwise fall under the lower repetition bound, provided the adjustment is transparent in the log. It is not an automatic drop set and must not disguise systematic fatigue or progressive collapse of Supporting Set performance.

If a load increase makes the Supporting Set miss its floor repeatedly, check progression criteria rather than raising the weight further.

## 5. Rest between working sets

Practical default ranges:

- **Compound / strength-relevant:** ~2.5–4 min.
- **Targeted / stable isolations:** ~1.5–3 min.

Extend rest if performance quality needs it; shorten only when it does not undermine the intended hard sets. The ranges are **organizational heuristics** and should not be portrayed as experimentally proven universal optima [R16]. Warm-ups and station transitions are included in time feasibility at the program level, whether or not the user's personal limit excludes warm-ups.

## 6. Technique, ROM and tempo

Use a **repeatable, tolerable, mechanically relevant ROM**, rather than forcing maximal range regardless of joint control or comfort. Controlled eccentric, purposeful concentric, and standardized execution allow valid progress comparisons. Do not prescribe theatrically slow tempos without a goal-based reason. Anatomy and exercise function determine whether long-muscle-length emphasis matters; evidence is context dependent [R18].

## 7. Weekly priority and counting

A two-set default says nothing about whether total weekly dose is appropriate. Chapter 02 records P/S and exposures; Chapter 06 determines initial weekly amount via **Baseline + Response**; Chapter 07 tests whether it is adequate for the outcome.

**STATUS: FINAL RULES — v1.0**

# HARDSET — Chapter 04: Exercise Selection & Safety

**Version:** v1.0 — APPROVED RULESET  
**Text status:** faithful editorial reconstruction of approved decisions; not guaranteed verbatim reproduction.  
**Principle:** **Criteria-First, Machine-Biased.**

## 1. The selection hierarchy

An exercise must first be **safe enough for its intended effort and context**. Then assess:

1. **Relevant Stimulus:** does the selected execution train the intended muscle/function?
2. **Repeatable Execution:** stable setup, usable ROM, controllable technique.
3. **Progression Potential:** can challenge be increased or performance compared without arbitrary changes?
4. **Manageable Non-Target Fatigue:** does the exercise consume too much back, grip, cardiorespiratory or systemic capacity for the target achieved?
5. **Practical Access:** available equipment, user competence, changeover time and preferences.

A popular or 'hardcore' lift is not automatically best. An exercise should earn its place in the program.

## 2. Machine bias is conditional, not ideological

When two candidate exercises offer broadly comparable relevant stimulus and execution quality, HARDSET **often favors stable machines**, especially when the user trains alone close to failure. The rationale is easier setup, predictable stop and potentially lower technical demands. It is **not** a claim that machines necessarily build more muscle than free weights; the comparative evidence does not establish such an advantage [R12].

Free weights remain completely valid for specific strength, skill, preference or practicality. Test specificity matters: improving free-weight competition lifts requires their practice.

## 3. Safe Failure Access

For **0 RIR**, verify that the lifter can stop or safely escape **without assistance even when another repetition cannot be performed**. Document the mechanism: machine stops, safety bars, spotter, easy disengagement or ability to release the implement safely. A free-weight exercise with uncertain termination should receive an appropriate **failure-conservative override (usually 1–2 RIR)** or substitution.

Examples, dependent on machine design and individual setup:

| Exercise | Practical guidance |
|---|---|
| Pec deck / cable triceps / leg curl | Often compatible with a safe near-failure endpoint, but inspect the machine and position. |
| Machine chest press | Often appropriate, if the return/stop is controlled. |
| Bench press | Conditional on appropriately adjusted safeties or sufficient spotting; avoid uncontrolled failure. |
| Hack squat / leg press | Conditional on catches, ROM, and ability to stop safely under fatigue. |
| Heavy Romanian deadlift / unsupported hip hinge | Usually keep ~1–2 RIR due to positional and recovery cost. |

These are conditional examples, not universal medical or mechanical safety certifications.

## 4. Useful Range of Motion

Aim for the largest **repeatable, mechanically relevant, comfortable/tolerable** range for the user and goal. No forced mobility, joint compensation or pain provocation for a theoretical extra centimeter. Respect meaningful local variation in muscle function. Record execution changes, since a deeper or shallower variation may make kilogram comparisons unreliable.

## 5. Purpose-Preserving Substitution

Every swap must preserve the **training purpose** of the original, not merely resemble its name:

- **Direct:** same principal function and P/S role, compatible progression and safety; can replace with modest adjustment.
- **Conditional:** target remains but changes in functional emphasis, fatigue or exposure require checks.
- **Invalid:** the replacement fails the original target or introduces a relevant gap.

Examples: replacing a chest press with a different chest press may be Direct if mechanics and tolerability are comparable; substituting a vertical pulldown for a rear-delt-targeted exercise is usually not Direct. Substituting equipment changes load meaning; **do not compare kilograms across different machines** as though they were identical.

## 6. Exercise continuity

Keep a useful exercise long enough to evaluate progress. Change when it is painful, unsafe, unavailable, ineffective for intended function, no longer aligned with goals or imposes disproportionate fatigue. Do not rotate exercises by calendar habit. When changed, restart the progression baseline and update movement and P/S tags.

## 7. Scope of safety

HARDSET assesses exercise setup and foreseeable risks; it **cannot clear a person medically**. New severe symptoms, neurologic deficits, unexplained pain or significant limitations require appropriate professional assessment, not merely a different RIR. The validator must mark unresolved safety risks as blocking rather than 'accepted compromise.'

**STATUS: FINAL RULES — v1.0**

# HARDSET — Chapter 05: Progression & Autoregulation

**Version:** v1.0 — APPROVED RULESET  
**Text status:** faithful editorial reconstruction of approved decisions; not guaranteed verbatim reproduction.  
**Principles:** **Lead-Set Progression; Qualified Progression.**

## 1. Progress the performance, not the number alone

Record **load, repetitions, estimated RIR and execution quality** for each Hard Set. Progress requires comparison under sufficiently similar conditions: same exercise variant and equipment, comparable ROM, technique, rest and intended effort. An unrepeatable cheat rep or compromised ROM is not valid progression.

## 2. The Lead-Set rule

For a two-set exercise with selected range `[L, U]`, consider the smallest practical weight increase **when all conditions hold**:

1. **Lead Set** (first Hard Set) reaches **U** correct reps at the prescribed RIR.
2. **Supporting Set** meets **at least L** correct reps with acceptable execution and the expected fatigue profile.
3. The observed performance is credible; range, equipment, assistance and technique were comparable.
4. The next loading step is appropriate to the exercise and user.

**Both sets do NOT need to reach U.** One credible achievement can justify progression; require a repeat if noisy, ambiguous or unusually favorable conditions make the result suspect. Do not force weight increases every session or week.

## 3. Load increments and calibration

Choose the smallest practical available increment, not one fixed percentage for every machine or person. After a load change, expect repetitions to decrease within the range. If a later set falls below the floor, a transparent ~5–10% back-off may be useful but should **not hide persistent Supporting Set degradation**. If a new machine is used, treat it as a new baseline.

RIR assessments can be imperfect, especially with lighter loads or limited practice [R19][R20]. Start a new variant with calibration, not a maximal test by default.

## 4. Day-to-day autoregulation

A single unusually weak workout **does not justify rewriting the program**. Review sleep, stress, illness, nutrition, warm-up, technique, rest, local soreness and schedule. If performance is unexpectedly low, reduce today's weight or effort sufficiently to keep intended quality. Document the adjustment and return to regular plan when feasible.

Persistent poor quality or pain needs earlier intervention than a scheduled review. Autoregulation must not mean ignoring warning signs just because the plan says to progress.

## 5. Plateau evaluation

Practical observation points (HARDSET heuristics, not validated biological cutoffs):

- After **~3–4 comparable exposures** without clear progress, check whether stagnation is real, including Supporting Set, recovery and execution.
- After **~4–6 weeks** of continued nonprogress under relevant conditions, consider changing a variable after identifying plausible causes.

These are **prompts to investigate**, not mandatory dates for adding sets or switching exercises. The presence of progressing loads is not direct proof of hypertrophy; lack of load progression is not proof that hypertrophy stopped (Chapter 07).

## 6. Volume decisions

Before adding work: check if the current dose is actually insufficient, whether exposure distribution causes excessive per-session fatigue, and if recovery can tolerate more. Options include **Keep / Expand / Reduce / Redistribute** (Chapter 06). Priority status does not guarantee a fixed volume increase.

## 7. Deload by need

Deload exists to manage accumulated fatigue, not to satisfy a calendar block. One practical example: **5–7 days**, about **40–60% fewer working sets**, and roughly **3–4 RIR**, with usual exercise selection and training opportunities generally preserved where workable. These figures are **illustrative implementation heuristics**, not physiological laws. A temporary reduction of exposures during deload does not rewrite Chapter 02's normal defaults.

The reason for deload can include systemic/local fatigue, declining results and inadequate readiness. On return, recheck load and quality rather than blindly restoring top weights. Maintenance (Chapter 08) is distinct from deload.

## 8. What not to do

Do not raise weight after a single invalid set; require both sets at upper range; use an automatic weekly load ladder; infer hypertrophy directly from rep records; prescribe a deload every fixed number of weeks; or change an entire plan after one bad day.

# HARDSET — Chapter 06: Weekly Programming & Recovery

**Version:** v1.0 — APPROVED  
**Text status:** editorially normalized approved final chapter.  
**Principle:** **Program the stimulus. Organize the week. Choose the split.**

## 6.1. Goal-First, Exposure-Aware

HARDSET organizes weekly training according to **individual goals, resources, recovery and constraints**, not one mandatory split or fixed muscle priorities. Construction order:

1. Determine goals and limitations.
2. Assign Priority / Standard / Optional to Fixed Core and activated Overrides.
3. Establish the initial weekly dose using **Baseline + Response**.
4. Plan P/S work and exposures.
5. Distribute work across available sessions.
6. Choose the split that serves that distribution.
7. Verify feasibility and recovery; iterate when incompatible.

For Priority and Standard, maintain the Chapter 02 default of **two weekly meaningful exposures** where feasible; document deliberate justified departures.

## 6.2. Two-Set Default vs weekly volume

Two Hard Sets is the **exercise-level default**, not a weekly muscle-volume prescription. An area can receive more work through multiple exercises, sessions or appropriately justified third sets. There is no universal rule that four weekly Primary sets suffice for ambitious hypertrophy goals. Research generally supports higher weekly volume on average with diminishing returns [R01][R02][R07].

## 6.3. Weekly Stimulus Ledger

For each relevant area record:

- **Weekly Primary Sets:** sum of physical Hard Sets tagged P for the area.
- **Secondary Work:** list of hard sets from movements tagged credible S, **separate**, with no fixed equivalence multiplier.
- **Weekly Exposures:** count of sessions containing meaningful P or credible S, max one per session.
- **Training Response:** performance, tolerance and goal-relevant outcome observations.

A set may be reflected in multiple muscle ledgers, but it remains **one physical set** for time and total workload. The weekly ledger tracks coverage; it cannot certify maximal hypertrophy.

## 6.4. Baseline + Response

If there is a previous **effective and tolerated** weekly dose, begin around that dose after adjusting for current conditions. With poor data, use a conservative reasonable baseline and monitor. More volume can be programmed from day one when justified by history and goal. No fixed P-set number attaches automatically to Priority or Standard. Numeric volume categories live **only in a non-normative Appendix** (Appendix A).

Priority gets first claim on scarce resources, Standard receives regular goal-appropriate work, Optional no obligatory sets/exposures. Reassign priorities only intentionally, not silently to make the generator pass.

## 6.5. Exposure distribution

Normally distribute meaningful work **relatively evenly** to protect quality; allow asymmetry when needed. Eight P sets might be 4+4 across two sessions or 3+3+2 across three. Neither split guarantees more growth simply by its shape. More than one P exercise in one session does **not** create extra exposures.

No universal maximum sets per muscle per session is asserted. If later sets regularly deteriorate, test exercise order, rest, redistribution and total workload.

## 6.6. Split Neutrality

Full Body, Upper/Lower, Push/Pull/Legs and hybrids are all allowed. Four decision tests:

- **Coverage:** intended muscles/functions and exposures.
- **Capacity:** available days, session length and facilities.
- **Quality:** meaningful hard sets remain high quality.
- **Recovery:** repeated sessions are tolerable.

Illustrative—not mandatory—starting structures:

| Weekly sessions | First configurations to inspect |
|---:|---|
| 1 | Usually Full Body, explicitly accept missed two-exposure default |
| 2 | Usually Full Body ×2 |
| 3 | Full Body ×3 or hybrid |
| 4 | Upper/Lower ×2, Full Body or hybrid |
| 5 | Hybrid with a specific reason for the fifth session |
| 6 | PPL ×2 or another well-recovered architecture |

Split-versus-Full Body comparisons under equated volume generally show similar hypertrophy [R11]. Frequency commonly functions as a **volume-distribution tool**, not a magic hypertrophy variable when volume is matched [R10].

## 6.7. Session Quality and scheduling

Place priority tasks where appropriate output is possible; rotate ordering for comparable priorities if useful. Respect local fatigue, overall load, sleep, work, recovery and other sports. No universal strict 48–72-hour recovery gap is imposed.

Running/cycling/other activities are **external constraints**, never universal mandatory components. Concurrent training can coexist with hypertrophy, although explosive strength and individual fatigue may require scheduling care [R15].

## 6.8. Four Volume Responses

- **Keep:** work and recovery suit present goals.
- **Expand:** additional stimulus is justified and tolerable.
- **Reduce:** workload or fatigue cost is excessive for current purpose.
- **Redistribute:** shift the same weekly dose among sessions to improve performance or logistics.

Changes follow Chapter 05 progression/autoregulation and Chapter 07 evidence quality.

## 6.9. Structural Validity ≠ Adaptive Adequacy

**Structural Validity:** all agreed constraints, tags, exposures, functions and safety requirements are correctly represented in the designed program.  
**Adaptive Adequacy:** observed outcomes support that the resulting dose serves the user's goals. One is inspected at design; the other requires real training data over time. A program can be structurally valid and still yield disappointing adaptation.

## 6.10. Feasibility, compromises and simplicity

If needs exceed the available time or recoverable workload, **report the conflict** and offer real options: more time/sessions, smaller dose, better distribution, or user-approved changed priorities. Do not fabricate P/S or exposures or automatically override goals. Avoid adding unnecessary sessions, symmetry, or hard set counts solely to make a chart look complete.

**Final principle: The split serves the program. The program serves the goal.**

# HARDSET — Chapter 07: Outcome Tracking & Program Evaluation

**Version:** v1.0 — APPROVED  
**Text status:** editorially normalized approved final chapter.  
**Principle:** **Measure what matters. Report what is known. Never invent certainty.**

## 7.1. Minimal Core + Goal-Specific Tracking

HARDSET can operate entirely on a **minimal training log**. Per Hard Set log:

- Exercise and equipment/variant.
- Load.
- Completed correct repetitions.
- Estimated RIR.
- Execution quality or noteworthy variation.
- Important condition/recovery problems as needed (not a compulsory long daily questionnaire).

Additional measurements are **optional and chosen for the goal**: strength tests, body mass trends, circumference, progress photographs or specialist measures. No one must own an ultrasound scanner, undergo DXA, or take daily physique pictures.

## 7.2. Three separate outcome layers

**Performance:** comparable exercise and task achievements, at similar technique, effort and conditions.  
**Outcome:** the user's declared end result—muscle size, strength or another relevant adaptation.  
**Sustainability:** adherence, tolerability, recovery and ability to keep training.

Keep statuses separate. Better performance does not *prove* hypertrophy; no training log trend alone can measure a muscle's size. At the same time, muscle growth and strength can be strongly associated in appropriate controlled conditions [R21]; the relationship is neither zero nor a universal conversion factor.

## 7.3. Evidence-limited evaluation

Users who collect only gym-log data can be evaluated for performance and available sustainability. Their hypertrophy status must be **Not Assessed**, not failed or automatically confirmed. Lack of measurements is not evidence that no change occurred.

Conversely, a person with an ambitious physique outcome and no suitable measurement cannot receive a scientifically justified claim of that outcome. A suggested measurement should remain optional.

## 7.4. Hypertrophy evidence stack

| Indicator | Supports | Does NOT establish |
|---|---|---|
| Load/reps/RIR trend | Task-specific performance | Direct measurement of muscle growth |
| Repeated circumference | Limb/body dimension changes | Muscle gain separated from fat and fluid |
| Standardized photos | Appearance changes | Exact tissue composition or mass |
| Repeated body mass | Total body mass trend | Muscle-specific change |
| Ultrasound local thickness | Size at measured location | Exact growth of entire muscle |
| MRI specific volume | More direct estimate of structure size | Perfect causal or total-body measurement |

Measurements should be made under reproducible conditions. Even local ultrasound thickness may not track whole-muscle MRI volume well for individuals [R22]. Early apparent size increases can partly reflect edema and transient swelling [R23]. No photographs, weight gain, pump, soreness, or 'feeling' should be used as direct proof of hypertrophy.

## 7.5. Standardization

For circumference: same anatomical site, tape tension and position, relaxed muscle, comparable time and conditions, avoid immediately post-workout pump.  
For photos: same distance, angle, lighting, stance and approximate conditions.  
For body mass: where applicable, consider **trends over several measurements**, not one day.  
For imaging: adhere to method-specific protocols and measurement uncertainty. A tiny measured change may be noise rather than response.

## 7.6. Practical review intervals

**These are planning heuristics, not biologically required deadlines**:

| Measure | Typical cadence |
|---|---|
| Hard Set log | Every working set |
| Relevant recovery issue | At session / when a problem arises |
| Program review | Around 6–8 weeks |
| Circumference (optional) | Around 4–8 weeks |
| Photos (optional) | Around 6–8 weeks |
| Hypertrophy outcome review | Often ~8–12 weeks or longer |

Very small changes, advanced trainees or noisy methods may warrant longer observation. Chapter 05 may require immediate day-to-day adjustments independently of a formal review.

## 7.7. Four independent outcome states

Assign **separately per target/outcome**, not one score for the person:

1. **Not Assessed:** no suitable data.
2. **Inconclusive:** measurements exist but are inconsistent, short-term or uncertain.
3. **Supported Progress:** reasonably coherent and suitable evidence supports improvement in that specific target.
4. **Concern:** repeated credible observations suggest a problem with achieving the target or tolerating training.

No mandatory fifth 'Failure' label; no invented numerical probability or arbitrary cutoff. Supported Progress is never a claim of absolute biological certainty. When reporting it, cite *which observations* support it.

## 7.8. Decision rules

- **Not Assessed:** no outcome verdict; optional better measurement; normal training progression continues.
- **Inconclusive:** prefer standardization and additional observation, not reflexive volume increases.
- **Supported Progress:** usually maintain what works and apply Chapter 05 progression.
- **Concern:** examine adherence, exercise quality, goal, nutrition/recovery, volume, fatigue and measurement issues; make the smallest justified change.

Safety concerns and pain do **not** wait for a scheduled outcome review.

## 7.9. Integration and simplicity

The training log informs progression in Chapter 05, weekly dose adjustment in Chapter 06 and focus decisions in Chapter 08. Avoid proprietary 'hypertrophy scores' derived from reps or DOMS, daily measurement burdens, obligatory 1RM tests, or overinterpretation of small changes.

**Final principle: Progress must match the goal, not just the logbook.**

# HARDSET — Chapter 08: Long-Term Planning & Specialization

**Version:** v1.0 — APPROVED  
**Text status:** editorially normalized approved final chapter.  
**Principle:** **Keep what works. Change what matters. Plan only what needs planning.**

## 8.1. Continuous Progression + Optional Focus Blocks

A stable program that fits the person's goals, yields useful work and is well tolerated **does not have an expiry date**. HARDSET does not mandate planned mesocycles, periodic complete exercise replacements, linear volume ramps, deload every N weeks or compulsory phase sequences. Periodization may be used when it serves a purpose, particularly specific maximum-strength performance, without claiming it is necessary for hypertrophy [R13][R01].

## 8.2. Three management situations

**Continuous Development:** normal sustained progression with justified small adjustments. Default.

**Focus Block / Specialization:** deliberate additional emphasis on one or more goals; optional and not intrinsically time-limited.

**Maintenance / Reduced Capacity:** intentionally preserving selected outcomes when resources or priorities change. May persist for months; is **not the same as a short fatigue-management deload**.

These are management modes, not mutually exclusive complete training philosophies. A program can develop one area while maintaining another.

## 8.3. Two independent dimensions per area

**Programming Priority:** Priority / Standard / Optional (from Chapter 02; resource allocation).  
**Training Intent:** Development / Maintenance (what change is sought in the period).

Do not conflate these. An Optional area is **not** automatically a maintenance target; not every Priority needs an automatic series increment. An area may be important but currently targeted for retention. If reducing training for a Standard or Priority area, document whether the exposure default is maintained or a justified exception applies.

## 8.4. Focus Block entry checklist

A Focus Block requires:

1. Concrete target: area, movement/ability and success criteria.
2. Current baseline: P sets, S work, exposure distribution, performance and tolerance.
3. Resource decision: **redistribute** current work first where sensible; **expand** overall dose only if justified and recoverable.
4. Targeted changes: priorities/intent, exercises, order, functions, volume and/or exposure distribution.
5. An outcome measure suited to the target (or explicit evidence limitation).
6. An approximate review point, **not an obligatory stop date**.

It need not require a new split. It should not silently eliminate other previously agreed goals.

## 8.5. Protection of nonfocus goals

For each area receiving less attention, document:

- What work/exposures are reduced and why.
- Whether Training Intent changes to Maintenance.
- Whether Priority/Standard two-exposure coverage still holds; if not, an explicit exception.
- What observable result would justify maintaining or revising the allocation.

Never claim maintenance solely because one lift is not falling. Outcome limitations from Chapter 07 still apply.

## 8.6. Maintenance

Maintenance is a **specific goal to preserve a defined adaptation**, not an unexplained small training dose. Lower volume than development can be enough for some people/contexts [R14], but there is no universal minimum working-set count that guarantees it. Establish an individual maintenance baseline from prior training; retain meaningful stimulus and usable intensity; reduce as warranted; observe outcomes.

A **deload** (Chapter 05) is a relatively brief reduction to manage fatigue. **Maintenance** can be long-term and does not require an automatic high RIR. Neither is tied to a compulsory calendar phase.

## 8.7. Review and phase transition

A phase may change when:

- The goal is achieved or priorities change.
- New capacity limits or life demands arise.
- There is sustained evidence of concern about results or tolerability.
- The user chooses a different target.

At transition: **retain effective exercises and standards where still relevant**, establish updated baselines, and avoid changing many variables without reason. After a period of reduced work, do not blindly resume past top loads or volume. Recalibrate and return to ordinary Chapter 05 progression.

An inconclusive 6–8-week review does not compel switching blocks. Do not confuse a planning checkpoint with a test of whether hypertrophy 'must' already be visible.

## 8.8. Integration

Chapter 02 defines goals by muscle; 03–04 define useful, safe exercises/sets; 05 progression/deload; 06 weekly resources and exposure; 07 quality of evidence; 09 construction and validation. Focus Blocks work **inside** all those constraints.

**Final principle: Consistency builds the foundation. Purposeful change directs adaptation.**

# HARDSET — Chapter 09: Program Construction & Validation

**Version:** v1.0 — APPROVED  
**Text status:** editorially normalized approved final chapter.  
**Principle:** **Build with purpose. Validate before execution. Adjust from evidence.**

## 9.1. Six-stage builder

**01 — Profile:** main and secondary goals, experience, training history, available days/time, equipment, exercise preferences, meaningful constraints, other activities and relevant safety limits. Do not assume any profile from prior plans.

**02 — Priorities & Intent:** for all 12 Fixed Core areas, assign Priority/Standard/Optional and relevant Development/Maintenance intent; add only justified Functional Overrides.

**03 — Weekly Stimulus:** establish baseline P sets, relevant S work and target exposures by area. Use **Baseline + Response**, not automatic set numbers by Priority.

**04 — Exercise & Split Selection:** choose exercises with Chapter 04 criteria and arrange the required stimulus across feasible sessions using Coverage/Capacity/Quality/Recovery tests.

**05 — Training Prescription:** assign exercise, set count, rep range, RIR, rest, ROM/execution and a clear Chapter 05 progression rule. The standard is two Hard Sets unless 1 or 3 is justified by Purpose/Value/Recovery.

**06 — Validation & Delivery:** perform all gates, repair issues, record accepted compromises, and publish an operational plan.

Builder is **iterative**, not linear-only. Failing time feasibility sends us back to earlier steps rather than silently discarding a goal.

## 9.2. Safety-First Gate

Prior to release check exercise suitability, equipment setup, safe termination of hard sets, ability to meet prescribed RIR, and unresolved risks. If the failure endpoint is unsafe, use a conservative RIR or different exercise. **A serious safety concern cannot be accepted as a Conditional compromise**; change the program or require qualified assessment.

A validator cannot clinically certify safety, individual technique or recovery. Its output means 'no identified blocking issues based on declared data,' not 'medically safe.' Unknown critical information may prevent PASS.

## 9.3. Coverage and exposure gates

For all 12 Fixed Core areas and active Overrides report:

- Priority / Training Intent.
- Physical P sets and separate S work.
- Credible sessions with P or S, at most one exposure per area/session.
- Functional Notes and gaps.
- Exceptions and rationales.

Priority: prefer P+P, P+S conditional on credible S and no important gap. Standard: P+P or credible P+S. S+S not automatically sufficient. Optional has no mandatory minimum. **S? does not count**. Do not infer P/S from the name of a machine or invent a fractional equivalent [Chapter 02].

## 9.4. Weekly dose and set architecture gate

Check if starting volume fits history and target, takes credible secondary work into account, is plausible for time/recovery, and allows future monitoring. This does not guarantee 'optimal' biological stimulus.

Check two-set default, justified 1/3 set exceptions, appropriate RIR for each specific exercise and safety context, stable rep templates and sufficient rest. No mandatory cap on more than three sets, but the planner must justify unusual deviations and workload.

## 9.5. Time and recovery gate

First clarify whether the stated time limit **includes** or **excludes warm-up**. Estimate working time from sets, rep tempo, rest, transitions, equipment availability and buffer. Do not assert precise minute-level truth without measuring. Respect external sport, work/life and local fatigue, not universal fixed muscle-rest hours.

A feasible plan respects the **actual** availability. If it doesn't, repair it or report a conflict; do not hide overrun.

## 9.6. Progression and evidence gate

Every prescribed exercise needs a progress rule consistent with Lead-Set Progression. Default minimum log: variant, load, reps, RIR, execution and relevant recovery notes. Goal-dependent measurement is optional; never claim hypertrophy verified from log alone.

## 9.7. Validator status definitions

| Status | Meaning |
|---|---|
| **PASS** | All mandatory construction checks supported by available declarations; no identified blockers. Does not guarantee future success or medical safety. |
| **CONDITIONAL** | Safe/feasible design with **explicit, justified and user-accepted** departure from a preference, OR non-blocking evidence limitation to be resolved. Conditional must never silently mean 'unsafe but permitted.' |
| **FAIL** | Identified blocker: unsafe prescribed action, infeasible time/capacity, or agreed non-negotiable constraint contradicted without resolution. |

The automated validator may also flag **NEEDS_REVIEW** as an *internal* status of a single check when data is missing; overall status maps it to CONDITIONAL or FAIL based on severity. Human judgment is required for P/S biomechanics and individual safety.

## 9.8. Required output

A released program contains: anonymous/current profile summary; goal and priority/intent map; weekly schedule; exercise list (sets/reps/RIR/rest/ROM cues); progression instructions; P/S ledger and exposure audit; safety notes; estimated time; tracking/review schedule; explicit exceptions; overall validator status.

## 9.9. Post-launch validation

After execution, recheck real session duration, exercise mechanics and equipment access, tolerability and goal-related results. Use Chapter 05 for progression, Chapter 06 for weekly organization, Chapter 07 for outcome interpretation and Chapter 08 for long-term transitions. One bad workout does not mandate a plan rebuild.

**Final principle: A plan is not complete when every exercise is listed. It is complete when its purpose, execution, constraints and evaluation are clear.**

# HARDSET — Appendix A: Weekly Volume Reference Guide

**Version:** v1.0 — NON-NORMATIVE SUPPORTING MATERIAL.  
**This appendix is not part of the binding main-chapter rules.**

## Orientation only

Ranges below count **Primary (P) Hard Sets per Fixed Core area per week**, as classified by the actual exercise variant and execution. They are **HARDSET implementation categories, NOT scientifically validated hypertrophy minima or maxima**.

| Volume label | Weekly P sets / area | Interpretation |
|---|---:|---|
| Below Low | 0–1 | May be intentional, especially Optional or significant credible S contribution |
| Low | 2–4 | Small dose / tentative baseline / limited resources |
| Moderate | 5–8 | Practical intermediate starting description |
| Expanded | 9–14 | More emphatic weekly direct work when justified |
| Individual High Volume | 15+ | Possible with individualized context and evidence of tolerance |

Do not directly compare these P-only labels to study-reported sets/muscle/week when study counting methods differ [R01][R02]. Do not use a universal S=0.5P constant. Do not assign all Priority areas to Expanded or all Standard to Moderate automatically.

## How to select baseline

1. If reliable past dosage and response exist, start from the **latest effective and well-tolerated dose**, adjusting to current schedule and goals.
2. Otherwise choose a conservative plausible initial dose, considering actual experience, other S work, constraints and expected recovery.
3. Define exposures and distribute work to preserve good performance.
4. Reassess through **Keep / Expand / Reduce / Redistribute**; adjust deliberately, not by crossing a numeric category line.
5. If time or recovery cannot support the goal, report the conflict instead of claiming success from the label.

## What this appendix must never do

- Substitute for chapters 02, 05, 06 or 07.
- Specify a universal optimal set number.
- Justify a guaranteed growth claim or automatically invalidate low-volume training.
- Provide a biological equivalence factor for Secondary sets.

**Evidence context:** average hypertrophy benefits of higher volume with diminishing returns [R01][R02][R07][R08]; not a claim that these category boundaries have been tested.

## Fixed Core map

**Upper Push:** Chest; Lateral Delts; Elbow Extensors.  
**Upper Pull:** Back; Rear Delts; Elbow Flexors.  
**Lower:** Quadriceps; Hamstrings; Glutes; Hip Adductors; Calves.  
**Trunk:** Trunk Musculature.

The labels map training responsibility, not a proof of uniform development. Wide areas may require Functional Notes. Functional Overrides do not silently redefine the fixed map.

## Correct use of P/S

- Horizontal press may be **Chest P**, **Elbow Extensors S** depending on technique and intended stimulus; not necessarily Lateral Delts S.
- A rear-delt isolation may be **Rear Delts P**.
- A leg curl may be **Hamstrings P**, while a knee-dominant leg press is often **Quadriceps P**; specific versions require assessment.
- A generic 'compound' entry should **not** automatically credit every anatomical contributor.
- Trunk stabilization under external load is not automatically a Trunk Musculature P or even a credible S exposure.

These are **illustrations requiring review**, not a database of universal biomechanical truths.

# HARDSET — Appendix C: Exercise Mapping & Purpose-Preserving Substitutions

**Status:** Implementation reference only; exercise mechanics must be checked in context.

## Assignment procedure

For each exercise:

1. Assign one **Movement Tag** (pattern or targeted function).
2. State the user goal and principal trained area; label that area P if stimulus is meaningful.
3. Identify any meaningful secondary areas supported by the exercise execution; label S.
4. Mark doubtful contributions **S?**, not guaranteed S; omit where there is no meaningful role.
5. Add Functional Notes when a broad area (Back, Trunk, Hamstrings, etc.) would conceal a meaningful gap.
6. Verify failure safety and ease of ending the set under intended RIR.
7. Record the actual equipment variant, ROM and grip/stance details needed for repeatability.

## Illustration table (never blindly auto-assign)

| Example movement | Likely primary | Potential secondary/notes | Common classification pitfall |
|---|---|---|---|
| Machine chest press | Chest P | Elbow Extensors S | Lateral Delts are not automatically meaningfully trained |
| Supported lat-focused pulldown | Back P | Elbow Flexors S | Back functional bias (lat-focused) matters |
| Upper-back-supported row | Back P | Rear Delts credible S **depending on elbow trajectory**; Elbow Flexors S | Row type matters for Rear Delts |
| Lateral raise | Lateral Delts P | — | Overcrediting Trunk |
| Reverse pec deck | Rear Delts P | — | Calling all Back P by default |
| Leg press | Quadriceps P in relevant variant | Glutes S? or S depending setup/ROM | Counting Hip Adductors P from participation |
| Seated leg curl | Hamstrings P | Knee-flexion Function Note | Assuming hip-hinge function fully covered |
| Machine hip thrust | Glutes P | Other contributions context-dependent | Treating it as direct Hamstrings P |
| Cable crunch | Trunk Musculature P | Trunk-flexion Function Note | Treating all trunk functions as covered |

## Direct / Conditional / Invalid substitution

**Direct:** retains relevant Primary and Secondary purpose, functional emphasis, effort safety, progression capacity and useful ROM. Equipment load baseline resets as needed.

**Conditional:** retains most purpose but may change regional emphasis, workload/fatigue or exposure ledger; must update those aspects.

**Invalid:** does not meet the original target or creates important unaddressed functional gap. Do not relabel the substitute purely because the exercise name belongs to same broad family.

## When to replace an exercise

Reasonable: pain, unsafe exit, unavailable equipment, no repeatable execution, severe non-target fatigue, updated goal or inadequate specific stimulus. Unreasonable: arbitrary weekly novelty. Recheck progression with the new variant; machine kilograms across models are not directly comparable.

# HARDSET — Appendix D: Progression, Autoregulation, Review Playbook

## At every exercise

1. Confirm movement standard and safe stop.
2. Ramp up with separate non-counting warm-up sets.
3. Perform Lead Set within rep range and at intended RIR.
4. Perform Supporting Set with appropriate rest, load and safety.
5. Record both sets and compare under similar conditions.
6. If Lead reaches range ceiling at target effort and Supporting meets floor with correct technique, propose smallest practical increase next exposure.
7. If performance is ambiguous or fatigued, repeat or recalibrate rather than forcing progression.

### Example — anonymous exercise

A prescribed movement is 2 × 6–10 at ~1 / 0–1 RIR. Lead 10 correct reps at target RIR, Supporting 7 correct reps, same standard: **candidate for a small increase**. Lead 10 but Supporting 4 (below floor) and ROM shortened: **no qualified progression**. No claim about hypertrophy follows from either record.

## Respond to a plateau

- Compare 3–4 recent, sufficiently comparable exposures as a practical signal to investigate.
- Check recovery, technique, rest, equipment, supporting set, consistency and goals.
- Persistent nonprogress over roughly 4–6 weeks *can* justify a change, depending on evidence.
- Consider workload redistribution before adding more series.
- If new pain or unsafe execution occurs, take action immediately and appropriately.

## Deload illustration

A possible brief response to accumulated fatigue is ~5–7 days at roughly 40–60% fewer Hard Sets and ~3–4 RIR, while preserving useful session rhythm. Recalibrate on return. **Not a mandatory algorithm.**

## Review hierarchy

- **During session:** safe execution and daily load adjustment.
- **After 2–3 sessions on new exercise:** basic calibration and time realism.
- **Around 6–8 weeks:** broader program review if useful.
- **Around 8–12 weeks or longer:** hypertrophy review if user collects appropriate measurements.

The periods above are implementation suggestions, not validated biological thresholds.

**Tytuł:** How many times per week should a muscle be trained to maximize muscle hypertrophy? A systematic review and meta-analysis of studies examining the effects of resistance training frequency.  
**Rodzaj:** Systematic review / meta-analysis.  
**DOI:** [10.1080/02640414.2018.1555906](https://doi.org/10.1080/02640414.2018.1555906).  
**Link bibliograficzny:** https://doi.org/10.1080/02640414.2018.1555906

**Uzasadniony wniosek:** Volume-equated hypertrophy effects largely similar across different weekly frequencies.

**Granice interpretacji:** HARDSET 2-exposure rule is organizational, not a biological must.

## R11 — Ramos-Campo et al. (2024)

**Tytuł:** Efficacy of Split Versus Full-Body Resistance Training on Strength and Muscle Growth: A Systematic Review With Meta-Analysis.  
**Rodzaj:** Systematic review / meta-analysis.  
**DOI:** [10.1519/JSC.0000000000004774](https://doi.org/10.1519/JSC.0000000000004774).  
**Link bibliograficzny:** https://doi.org/10.1519/JSC.0000000000004774

**Uzasadniony wniosek:** When volume equated, split vs full-body yielded similar hypertrophy and strength outcomes in reviewed studies.

**Granice interpretacji:** Small/moderate evidence base; individual schedules and fatigue still matter.

## R12 — Haugen et al. (2023)

**Tytuł:** Effect of free-weight vs. machine-based strength training on maximal strength, hypertrophy and jump performance – a systematic review and meta-analysis.  
**Rodzaj:** Systematic review / meta-analysis.  
**DOI:** [10.1186/s13102-023-00713-4](https://doi.org/10.1186/s13102-023-00713-4).  
**Link bibliograficzny:** https://doi.org/10.1186/s13102-023-00713-4

**Uzasadniony wniosek:** No consistent hypertrophy advantage for machines or free weights; strength has task specificity.

**Granice interpretacji:** Only subset measured hypertrophy; selection should account for skill/safety.

## R13 — Moesgaard et al. (2022)

**Tytuł:** Effects of Periodization on Strength and Muscle Hypertrophy in Volume-Equated Resistance Training Programs: A Systematic Review and Meta-analysis.  
**Rodzaj:** Systematic review / meta-analysis.  
**DOI:** [10.1007/s40279-021-01636-1](https://doi.org/10.1007/s40279-021-01636-1).  
**Link bibliograficzny:** https://doi.org/10.1007/s40279-021-01636-1

**Uzasadniony wniosek:** Periodization offered strength benefits in reviewed settings; no clear hypertrophy advantage when volume equated.

**Granice interpretacji:** Volume equalization, populations and block designs differ.

## R14 — Bickel, Cross & Bamman (2011)

**Tytuł:** Exercise dosing to retain resistance training adaptations in young and older adults.  
**Rodzaj:** Longitudinal controlled exercise study.

**Granice interpretacji:** Specific detraining/maintenance scenario; no universal maintenance-minimum sets.

**Tytuł:** Compatibility of Concurrent Aerobic and Strength Training for Skeletal Muscle Size and Function: An Updated Systematic Review and Meta-Analysis.

**Uzasadniony wniosek:** Concurrent endurance and strength training did not generally compromise hypertrophy/maximal strength; explosive strength may be attenuated.

**Granice interpretacji:** Individual workload and scheduling still important; not a personal tolerance guarantee.

**Link bibliograficzny:** https://doi.org/10.3389/fspor.2024.1429789

**Uzasadniony wniosek:** Rest interval length can influence quality of volume and possibly hypertrophy; a practical rest period should sustain output.

**Granice interpretacji:** Does not validate the precise HARDSET 2.5–4 / 1.5–3 min bands for every user.

**Tytuł:** Strength and Hypertrophy Adaptations Between Low- vs. High-Load Resistance Training: A Systematic Review and Meta-analysis.  
**Rodzaj:** Systematic review / meta-analysis.  
**DOI:** [10.1519/JSC.0000000000002200](https://doi.org/10.1519/JSC.0000000000002200).

**Uzasadniony wniosek:** Hypertrophy can develop across loading ranges; heavier loads generally favor maximal dynamic strength.

**Granice interpretacji:** Conditions often involved sets to failure; no universal best rep range.

**Tytuł:** Does Muscle Length Influence Regional Hypertrophy? A Systematic Review and Meta-Analysis.  
**Rodzaj:** Systematic review / Bayesian meta-analysis.  
**DOI:** [10.1055/a-2615-4935](https://doi.org/10.1055/a-2615-4935).  
**Link bibliograficzny:** https://doi.org/10.1055/a-2615-4935

**Uzasadniony wniosek:** Evidence about longer vs shorter mean muscle length suggests small/contextual differences; caution with sweeping claims.

**Granice interpretacji:** Studies differ in achieved muscle-length contrasts, muscles and regional measures.

**Tytuł:** Repetitions in Reserve Is a Reliable Tool for Prescribing Resistance Training Load.

**Tytuł:** Estimating Repetitions in Reserve for Resistance Exercise: An Analysis of Factors Which Impact on Prediction Accuracy.

**Granice interpretacji:** Small sample and limited lifts/loads; RIR remains an estimate, not objective truth.

**Tytuł:** Ultrasound Muscle Thickness Is a Poor Index of Criterion Magnetic Resonance Imaging Measures of Resistance Training-Induced Muscle Growth.

## Rules for Claude / implementer

1. A scientific paper supports only the **specific limited claim** in its row.
2. NEVER upgrade an internal design decision into a research finding.
3. The absence of evidence in one direction is not always proof of no effect.
4. Numeric heuristics in annexes are removable without changing HARDSET v1.0.
5. Before citing a source, check authors, title, publication year, DOI and intended claim.
6. If evidence conflicts or is outside the studied population, disclose limitations instead of forcing a conclusion.

# HARDSET — Research audit and exclusion log

**Date of review:** 2026-11-12.  
**Scope:** metadata verification and claim-to-source reconciliation for this Knowledge Pack; not a new systematic literature search.

## Method

1. Verify paper titles, author names, year and DOI in PubMed, PMC or publisher pages.
2. Compare each claimed conclusion against the actual abstract or key results; avoid extrapolating from a title.
3. Label HARDSET conventions and practical numeric heuristics separately from research findings.
4. Keep uncertainty in view; neither null findings nor a meta-analytic estimate create a universal guarantee.
5. Exclude any source found to be retracted, and document it below.

## Important excluded article (retraction)

**Do not cite as supporting evidence:** Hughes, Peiffer & Scott, *Estimating Repetitions in Reserve in Four Commonly Used Resistance Exercises*, DOI **10.1519/JSC.0000000000003865**. The publication is marked **RETRACTED** by the publisher, with a retraction notice DOI **10.1519/JSC.0000000000003977**. It is **not part of this package's 23 active references**. For the RIR-estimation discussion we instead rely on e.g. Mansfield et al. **R20**, Lovegrove et al. **R19**, and the broader methodological context. 

Publisher retraction status: https://doi.org/10.1519/JSC.0000000000003865  
Retraction notice: https://doi.org/10.1519/JSC.0000000000003977

## Other important interpretation controls

- The ACSM overview in **R01** synthesized many reviews; its summarized ≥10 weekly sets/muscle finding is **not** an empirically established cutoff of 10 Primary HARDSET sets.
- **R02** tested alternative statistical rules for counting indirect work; its 'fractional' method is **not** a universal biological S:P conversion factor.
- The momentary-failure literature (**R03–R06**) does not show that an exact 1 RIR followed by 0–1 RIR pattern is universally optimal.
- **R10–R11** support flexible frequency/split selection under equated volume; they do not mean frequency, skill practice or scheduling never matters.
- **R13** does not rule out periodization for specific strength goals.
- **R14** cannot set a universal maintenance volume across ages and training backgrounds.
- **R21** documents strong size–strength correlations in one protocol; it does not allow estimating hypertrophy precisely from the logbook.
- **R22** identifies a specific limitation of local ultrasound thickness relative to MRI; it does not render all ultrasound measurements worthless.
- **R23** is evidence of early edema confounding certain measures, not a claim that early training cannot cause hypertrophy.

## Publication dates and limits

The package is current to **2026-11-12** for the cited studies. Evidence will evolve; do not represent the source set as an exhaustive review of all literature. Most findings concern healthy adult participants; precise applicability to rehabilitation, children, pregnancy, or specialized medical populations requires separate evidence and appropriate professional input.

## Preservation and editorial honesty

Approved HARDSET Chapters 01–09 are preserved at the **rule level**. Chapters 01–05 have been reconstructed from approved decisions because their exact final artifacts were not fully present in the available working context. Chapters 06–09 have been editorially normalized from final approved draft content. These distinctions are also documented in `PROVENANCE.md`.

# HARDSET — deterministic structural validator (prototype)

**This is not an app and is not a complete AI plan generator.** It is a small Python command-line prototype that demonstrates testable rule checks required by Chapter 09. Python 3.10+; standard library only.

```bash
python validation/validator.py examples/generic_pass.json
python -m unittest discover -s validation/tests -v
```

The CLI prints JSON with `status` and messages; exit code 0 = PASS, 1 = CONDITIONAL, 2 = FAIL or malformed input.

## Core behaviors

- Expects all 12 Fixed Core areas to be declared explicitly (no default Priority assignments).
- Separately records P sets, credible S sets, uncertain S? counts, and session-level P/S exposures.
- Counts max one exposure per area per session, with P taking precedence.
- Requires ≥2 credible exposures for Priority/Standard, including at least one P; `S+S` is not automatically enough.
- An accepted and documented exposure exception can produce CONDITIONAL, not PASS.
- Inspects work set count and whether nondefault set counts have documented justification.
- Blocks any planned `rir_targets` below 1 if safe termination has not been positively declared.
- Estimates session time with per-set duration, within-exercise rest, transitions and a buffer; conservatively marks near-limit estimates CONDITIONAL.
- Checks progression rule presence but does not implement all training decisions or compute hypertrophy.

## Deliberate limitations

- **P/S tags are supplied by the planner, not guessed from names.** The tool cannot judge biomechanics from a string.
- **Risk and safety flags are supplied, not certified.** Even PASS is not a medical clearance or guarantee of zero injury risk.
- The time model is approximate and does not know gym crowding, warm-up length if not provided, machine maintenance or actual tempo.
- It cannot decide baseline suitability, actual recovery, development vs maintenance dose or realized biological outcome. These require human/AI **interpretation with evidence limits**.
- Python implementation is a demonstration. For production integration, require a documented schema, independent test cases, versioning, security review and real exercise-selection data.

## Example JSON shape

```json
{
  "constraints": {
    "session_time_limit_min": 60,
    "time_includes_warmup": false,
    "transition_min_per_exercise": 1.5,
    "margin_min_per_session": 5
  },
  "areas": {
    "Chest": {"priority":"Standard","intent":"Development"},
    "Back": {"priority":"Standard","intent":"Development"},
    "Lateral Delts": {"priority":"Optional","intent":"Development"}
  },
  "functional_overrides": {},
  "sessions": [
    {"name":"Session A","exercises":[{
      "name":"Stable press","variant":"Machine model A",
      "sets":2,"rir_targets":[1,0],"safe_exit":true,
      "rest_sec":150,"seconds_per_set":45,
      "progression_rule":"Lead-Set upper bound, Support floor",
      "stimulus":{"Chest":"P","Elbow Extensors":"S"}
    }]}
  ]
}
```

**Note:** sample shape above intentionally omits the remaining required Fixed Core declarations. Use `examples/generic_pass.json` for a complete valid input.

## Authoring directives for Claude

Never mark a program PASS just because the validator prints PASS. First inspect the input tags, risk declarations, personal suitability, volume baseline and accepted deviations. The validator checks **consistency**, not scientific certainty or actual training success.

# HARDSET Validator — Input Contract v0.1

Machine-readable input: JSON object, UTF-8. Examples in `../examples/`. No JSON schema library is needed to run the prototype; the contract below is descriptive. A future production package should publish an executable JSON Schema and type definitions.

## Top-level required objects

| Property | Type | Meaning |
|---|---|---|
| `goals` | nonempty list of strings | User-declared intent, never inferred |
| `human_review` | object | Attestation, not a clinical clearance |
| `constraints` | object | Schedule time/buffer parameters |
| `areas` | object | Exactly the 12 Fixed Core keys as defined in Chapter 02 |
| `functional_overrides` | object | Optional additional named targeted functions, same area schema |
| `sessions` | list of objects | Actual physical sessions, not days automatically inferred from name |

## `human_review`

Boolean `true` for each independent reviewed item: `goal_fit`, `ps_mechanics`, `exercise_safety`, `recovery`. Missing items produce CONDITIONAL. Reviews **attest only** that a qualified human/programmer has considered the issue, not that the validator confirmed it independently.

## `constraints`

- `session_time_limit_min` (positive number; missing produces CONDITIONAL)
- `time_includes_warmup` (boolean)
- `warmup_min` if time includes it; otherwise not needed for working portion.
- `transition_min_per_exercise` (nonnegative, default 1.5)
- `margin_min_per_session` (nonnegative, default 5)

Time estimate = Σ `sets * seconds_per_set + (sets−1) * rest_sec` over exercises, converted to minutes, + transitions + margin + applicable warm-up. This estimates **intra-exercise recovery** and transitions; not all real world delays are predictable. Near-capacity session (>90% budget) becomes CONDITIONAL.

## Each `areas` entry

| Field | Allowed |
|---|---|
| `priority` | `Priority`, `Standard`, `Optional` |
| `intent` | `Development`, `Maintenance` |
| `functional_gap` | optional boolean; `true` must be resolved or accepted exception |
| `accepted_exception` | explicit rationale for departing from coverage; string |
| `exception_accepted_by_user` | `true` required with rationale to reduce coverage FAIL to CONDITIONAL |

The `priority` values must be supplied deliberately; no default priority for any specific region.

## Session and exercise

Each session has unique `name` and `exercises` list. Each exercise:

- `name`: descriptive label; used only for output (not physiology inference).
- `variant`: exact equipment/variant; missing gives CONDITIONAL.
- `sets`: positive integer; default policy 2.
- `set_reason`: required if sets != 2; >3 also produces CONDITIONAL review.
- `rir_targets`: numeric list of length == sets; individual values ≥0.
- `safe_exit`: boolean; must be **true** for any planned RIR below 1.
- `known_safety_blocker`: boolean; `true` always FAIL.
- `rest_sec`: number ≥0, suggested but not universal.
- `seconds_per_set`: number >0, rough estimate.
- `progression_rule`: nonempty string.
- `stimulus`: dictionary of area name -> `P`, `S`, `S?`, `?` or `-`.

The algorithm cannot validate whether a `P` classification is biomechanically appropriate. A human must review actual movement, equipment, execution and intended target.

## Output

`status`: PASS / CONDITIONAL / FAIL.  
`ledger`: per-area P/S counts and a session map `P` or `S`; uncertain S? sets separate.  
`summary`: session count and total physically executed Hard Sets.  
`session_time_estimates_min`: model estimate per session.  
`findings`: each with severity, code, scope and message.

`PASS` is **structural verification of the declarations only**. It is not a guarantee of hypertrophy, optimal weekly volume, medically safe performance, accurate RIR or equipment suitability.

# HARDSET — Validation Test Suite Overview

The executable tests live in `validation/tests/test_validator.py` and run with:

```bash
python -m unittest discover -s validation/tests -v
```

## Cases covered

1. Completely declared generic 2-session plan with enough P exposures -> PASS.
2. S? cannot create a credible second exposure -> FAIL.
3. Same exposure defect with **documented, user-accepted exception** -> CONDITIONAL.
4. Written exception without explicit user acceptance still -> FAIL.
5. 0 RIR prescribed without positively verified safe exit -> FAIL.
6. S + S without P for Standard -> FAIL, not automatically valid.
7. Multiple exercises in one session yield at most one exposure per muscle.
8. Estimated time above agreed budget -> FAIL.
9. Three sets without reason -> FAIL; with valid reason can PASS.
10. Optional region may have zero meaningful P/S without affecting pass.
11. Unknown claimed muscle area -> FAIL; no fake Fixed Core expansion.
12. Missing goals / missing human review -> CONDITIONAL.
13. Validator must not mutate input data while evaluating.
14. Duplicate session identifiers are rejected rather than merged silently.
15. Missing warm-up/time-budget interpretation gives a Conditional warning.
